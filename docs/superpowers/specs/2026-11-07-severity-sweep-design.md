# Клінічна шкала тяжкості та точка руйнування — дизайн

Дата: 2026-11-07
Підпроєкт A дорожньої карти розвитку (ідеї 1 і 2 з `Ідеї.docx`).

## 1. Мета і контекст

Робота виконується для магістерської. Мета — дати експериментальне
підґрунтя твердженню зі статті про «точку руйнування» (приклад
«катаракта рівня 0.7 / 0.4») і отримати для розділу експериментів:

- криві ILR(тяжкість) для кожної вади зору;
- два пороги на кожній кривій — початок деградації і точку руйнування;
- клінічний зміст кожного значення тяжкості («s = 0.3 = 20/40»).

Узгоджені рішення:

| Питання | Рішення |
|---|---|
| Одиниці тяжкості | Гібрид: нормалізована s ∈ [0, 1] з явним відображенням у клінічну шкалу |
| Фіксація погляду для втрати поля зору | Сторінка ріжеться на фрагменти висотою з viewport, фіксація в центрі кожного |
| Пороги | Деградація: ILR ≥ 5 %; руйнування: ILR ≥ 50 %; обидва змінні з CLI |
| Підхід | Моделі тяжкості — єдине джерело параметрів; звичайні симуляції стають пресетами; окремий режим `--sweep` |
| Модель видимості | Спостерігач за Peli (1990) з CSF, підігнаною під logMAR і Pelli-Robson log CS |
| Еталон | Оригінал теж проходить через нормального спостерігача |

Поза межами цього підпроєкту: точка руйнування для окремих областей
сторінки (потрібні межі елементів із DOM — підпроєкт B), поріг якості
для режиму `--sweep`, HTML-звіт (підпроєкт E).

## 2. Геометрія перегляду (`viewing.py`)

```python
@dataclass(frozen=True)
class ViewingConditions:
    distance_cm: float = 60.0
    ppi: float = 109.0   # 27" 2560×1440
    dpr: float = 1.0     # фізичних пікселів на CSS-піксель
    viewport_height_px: int = 1440   # висота фрагмента для фіксацій
```

`viewport_height_px` береться з `--viewport` і визначає висоту фрагментів
для моделей поля зору, тому окремий параметр `tile_height` не потрібен.

Скріншот знімається з `deviceScaleFactor = 1`, тому 1 піксель зображення
= 1 CSS-піксель, фізичний розмір якого `25.4 · dpr / ppi` мм.

- `px_per_degree = 2 · distance_mm · tan(0.5°) / pixel_mm`
  (за замовчуванням ≈ 44.9 px/град, ширина viewport 2560 px ≈ 57°).
- `nyquist_cpd = 0.5 · px_per_degree` (≈ 22.4 цикл/град).
- `deg_to_px(deg)`, `px_to_deg(px)`, `cpd_to_cycles_per_px(f)` і навпаки.

Усі значення > 0, інакше `ValueError`.

## 3. Модель спостерігача (`observer.py`)

### 3.1 CSF спостерігача

Лог-парабола Lesmes et al. (2010) з усіканням на низьких частотах:

```
log10 S(f) = log10 γmax − κ · ( log10(f / fmax) / (β'/2) )²,   f ≥ fmax
log10 S(f) = max(parabola(f), log10 γmax − δ),                 f < fmax
κ = log10(2),  β' = log10(2β)
```

Фіксовані параметри: ширина смуги β = 3 октави, усікання δ = 0.5 log.
Вільні параметри визначаються двома клінічними числами в замкненій формі:

- **Контрастна чутливість:** `log10 γmax = logCS + 0.35`
  (норма log CS 1.95 → пік ≈ 200, типовий пік CSF здорового ока).
- **Гострота:** частота зрізу `f_cut = 30 · 10^(−logMAR)` цикл/град має
  давати S = 1:
  `fmax = f_cut / 10^((β'/2) · sqrt(log10 γmax / κ))`
  (норма → fmax ≈ 2.5 цикл/град).

`ObserverCSF(logmar, logcs)` перевіряє: `logcs > 0`, `logmar ≥ −0.3`.
`NORMAL_OBSERVER = ObserverCSF(0.0, 1.95)`.

### 3.2 Застосування (метод Peli)

`apply_observer(image_bgr, csf, viewing) -> image_bgr`:

1. sRGB → лінійний RGB (`gamma_decode`), float32, обробка по каналах.
2. Піраміда Лапласа (`cv2.pyrDown`/`cv2.pyrUp`) до рівня, де центральна
   частота смуги < 0.25 цикл/град, або поки менша сторона ≥ 8 px.
3. Центральна частота рівня k: `f_k = F0 / 2^k` цикл/піксель, де `F0` —
   геометричне середнє частоти половинного підсилення рівня 0 (≈ 0.13) і
   частоти Найквіста (0.5): `F0 ≈ 0.2565` цикл/піксель. Рівень 0 —
   високочастотний фільтр із піком на Найквісті, тому «пік» як центр не
   годиться. Значення виміряне синусоїдальними ґратками і закріплене
   константою з тестом. Переведення в цикл/град через `viewing`.
4. Локальний контраст: `c_k = B_k / L_{k+1}↑`, де `L_{k+1}↑` — низькочастотний
   рівень під смугою, піднятий до розміру смуги (захист від ділення на 0:
   `max(L, 1e-4)`).
5. Поріг: смуга обнуляється в пікселях, де `|c_k| < 1 / S(f_k)`.
   Смуги з `f_k` вищою за частоту Найквіста дисплея не існують у зображенні
   і окремо не обробляються.
6. Збірка піраміди, обрізання до [0, 1], `gamma_encode`.

Вимоги: середня яскравість зберігається з точністю до 2 рівнів sRGB
(низькочастотний залишок не змінюється, але жорстке відсікання смуг не
симетричне, тому точного збереження немає — у лінійному просторі зсув
до ~4 % на тексті); для кадру 2560×16384 час ≤ 3 с на типовому ПК.

## 4. Моделі тяжкості (`severity.py`)

```python
@dataclass(frozen=True)
class SeverityModel:
    key: str             # "cataract"
    name: str            # "Катаракта"
    unit: str            # "logMAR", "log CS", "°", "Machado", "M-CHARTS °"
    to_clinical: Callable[[float], float]
    format_clinical: Callable[[float], str]   # 0.3 -> "20/40"
    simulate: Callable[[np.ndarray, float, ViewingConditions], np.ndarray]
```

`simulate` перевіряє `0 ≤ s ≤ 1` (`ValueError`). Кожна модель — композиція
«оптика → спостерігач». При s = 0 результат дорівнює
`apply_observer(image, NORMAL_OBSERVER, viewing)`.

| key | Клінічне значення від s | Оптика | Спостерігач |
|---|---|---|---|
| `acuity` | logMAR = 1.0·s | — | `ObserverCSF(1.0·s, 1.95)` |
| `cataract` | logMAR = 1.0·s, log CS = 1.95 − 1.05·s | пожовтіння (B ×(1 − 0.3s), G ×(1 − 0.08s)), засвітка (змішування з білим, вага 0.3s) | `ObserverCSF(1.0·s, 1.95 − 1.05·s)` |
| `contrast` | log CS = 1.95 − 1.5·s | — | `ObserverCSF(0, 1.95 − 1.5·s)` |
| `scotoma` | радіус = 10°·s | центральна зона кожного фрагмента замінюється зоною «втраченого поля» | нормальний |
| `tunnel` | s = 0: поле не обмежене (нормальний спостерігач); s > 0: радіус поля = 30° − 28°·s | усе поза колом кожного фрагмента замінюється зоною «втраченого поля» | нормальний |
| `protanomaly`, `deuteranomaly`, `tritanomaly` | severity Machado = s | `simulate_anomalous_trichromacy_machado` | нормальний |
| `metamorphopsia` | M-CHARTS = 2°·s | синусоїдальне зміщення, амплітуда 2°·s, період 3° | нормальний |

Формати: logMAR → «20/NN» (NN = 20·10^logMAR, округлення до 5) та
«logMAR 0.30»; log CS → «log CS 1.20»; градуси → «5°», «0.5°» (`{round(v, 1):g}°`).

Зона «втраченого поля» — зображення після
`apply_observer(image, LOST_FIELD_OBSERVER)`, де
`LOST_FIELD_OBSERVER = ObserverCSF(1.6, 0.3)`. Межа кола розмита гаусом
із σ = 1° (у пікселях за `viewing`).

Фіксація: `tile_fixations(height, width, tile_height)` повертає центри
фрагментів `(width/2, top + h_tile/2)`; останній неповний фрагмент має
фіксацію у своєму центрі. `tile_height = viewing.viewport_height_px`.

Опорні точки (перевіряються тестами): s = 0.3 для `acuity` → «20/40»
(межа для водіння); s = 1 → «20/200» (законодавча сліпота, США);
s = 0.714 для `tunnel` → 10° (критерій сліпоти за полем зору).

Метаморфопсія має **наближений** зв'язок із клінікою (відображення
M-CHARTS → амплітуда синусоїди — припущення моделі); це явно зазначається
у звіті і в тексті роботи.

Не беруть участі в прогоні по шкалі (бінарні стани або без клінічної
шкали): ахроматопсія, дихромазія Brettel / Viénot, флоатери.

## 5. Пресети звичайного прогону (`config.py`)

`SIMULATIONS` залишається словником «назва → функція(image)», але функції
будуються з моделей із поточною `ViewingConditions`, а назва містить
клінічне значення:

| Назва | Модель, s |
|---|---|
| Гострота зору (20/40) | acuity 0.3 |
| Гострота зору (20/100) | acuity 0.7 |
| Катаракта (20/40) | cataract 0.3 |
| Катаракта (20/100) | cataract 0.7 |
| Втрата контрасту (log CS 1.20) | contrast 0.5 |
| Центральна скотома (5°) | scotoma 0.5 |
| Тунельний зір (10°) | tunnel 0.714 |
| Протаномалія (Machado 0.6) | protanomaly 0.6 |
| Метаморфопсія (0.5°) | metamorphopsia 0.25 |
| Метаморфопсія (1.5°) | metamorphopsia 0.75 |
| Ахроматопсія (Скотопічна) | фіксована + нормальний спостерігач |
| Протанопія / Дейтеранопія / Тританопія (Brettel) | фіксовані + нормальний спостерігач |
| Флоатери (Діабет. рет.) | фіксована (seed 42) + нормальний спостерігач |

Оскільки `ViewingConditions` задається з CLI, `SIMULATIONS` стає функцією
`build_simulations(viewing)`; константа для зворотної
сумісності не зберігається.

## 6. Прогін по шкалі (`sweep.py`)

```python
@dataclass
class SweepPoint:
    severity: float
    clinical: float
    clinical_label: str
    ilr: float | None
    error: str | None = None

@dataclass
class SweepCurve:
    model_key: str
    points: list[SweepPoint]
    onset: float | None      # s, інтерпольоване; None — не досягнуто
    breaking: float | None
    failed: bool = False
```

`run_sweep(image, baseline_word_set, models, viewing, steps,
onset_ilr, breaking_ilr, workers, ocr=get_word_data, image_sink=None)`:

- Сітка `s_i = i / steps`, i = 1..steps (s = 0 має ILR 0 за визначенням
  і додається в криву без обчислень).
- Точки обчислюються паралельно (`ThreadPoolExecutor`, `workers`).
  Якщо `--workers` не задано, в обох режимах використовується 4 потоки:
  одна точка на кадрі 2560×16384 у float32 займає ~1–2 ГБ пам'яті, тож
  стандартна кількість потоків Python (до 32) вичерпала б RAM.
- `ocr` інжектується — у тестах це фейкова функція.
- `image_sink(model_key, s, image)` викликається, якщо задано
  `--save-sweep-images`.
- Помилка в точці → `ilr=None`, `error=str(e)`; прогін триває.
- Модель `failed`, якщо не вдалося > 50 % точок.

`find_threshold(points, threshold)` — перший перетин при проході від
меншої тяжкості до більшої серед успішних точок: між останньою точкою
нижче порогу і першою ≥ порогу — лінійна інтерполяція s. Немонотонність
після першого перетину ігнорується. Не досягнуто → `None`.

Тека: `<output_dir>/sweep/`.

**`sweep.json`:**

```json
{
  "url": "...",
  "created": "2026-11-07T12:00:00",
  "viewing": {"distance_cm": 60, "ppi": 109, "dpr": 1,
              "px_per_degree": 44.9, "nyquist_cpd": 22.4},
  "baseline_word_count": 745,
  "thresholds": {"onset_ilr": 0.05, "breaking_ilr": 0.5},
  "models": [
    {"key": "cataract", "name": "Катаракта", "unit": "logMAR",
     "failed": false,
     "onset": {"severity": 0.21, "clinical": 0.21, "clinical_label": "20/30"},
     "breaking": null,
     "points": [{"severity": 0.1, "clinical": 0.1,
                 "clinical_label": "20/25", "ilr": 0.02, "error": null}]}
  ],
  "timing": {"total_s": 210.4}
}
```

ILR і пороги в JSON — частки (0..1); у консолі та на графіку — відсотки.

**`sweep_ilr.png`** (matplotlib, бекенд Agg): по одній панелі на модель
(сітка 3×3), вісь X — s з другим підписом клінічних значень, вісь Y —
ILR %, горизонтальні лінії порогів, вертикальні маркери знайдених
точок. Для тексту роботи — 300 dpi.

**Консоль:** таблиця «Модель | Деградація (s, клінічне) | Руйнування
(s, клінічне)», для не досягнутих — «> 1.0».

## 8. CLI (`main.py`)

| Прапорець | За замовчуванням | Опис |
|---|---|---|
| `--sweep` | вимкнено | режим прогону по шкалі замість звичайного |
| `--sweep-steps N` | 10 | кількість точок сітки (≥ 2) |
| `--onset-ilr P` | 5 | поріг деградації, % |
| `--breaking-ilr P` | 50 | точка руйнування, % |
| `--distance-cm D` | 60 | відстань до екрана |
| `--ppi P` | 109 | щільність пікселів екрана |
| `--dpr R` | 1 | device pixel ratio |
| `--save-sweep-images` | вимкнено | зберігати PNG для кожної точки |

Перевірки на старті (до скріншота): `0 < onset < breaking ≤ 100`,
`distance, ppi, dpr > 0`, `steps ≥ 2` — інакше помилка argparse (код 2).

Потік даних (обидва режими):

```
скріншот → load_image → apply_observer(NORMAL) → OCR → еталон
  звичайний: build_simulations(...) → process_simulation → таблиця / консоль / --max-ilr
  --sweep:   run_sweep(MODELS) → sweep.json, sweep_ilr.png, таблиця в консолі
```

Коди виходу без змін: 0 — гаразд; 1 — перевищено `--max-ilr` (лише
звичайний режим); 2 — помилка (зокрема `failed` модель або порожній
еталон).

Якщо частота зрізу нормального спостерігача (30 цикл/град) вища за
`nyquist_cpd`, у консоль виводиться довідка, що легке зниження гостроти
не впливатиме на результат, — це очікувана поведінка, не помилка.

## 11. Критерії приймання

1. Усі тести проходять (включно з калібрувальним при встановленому
   Tesseract).
2. Справжній `--sweep` на сторінці Вікіпедії за замовчуванням:
   - криві монотонні з точністю до шуму OCR (жодного падіння ILR > 5 п.п.
     між сусідніми точками);
   - для кольорових моделей поріг деградації високий (s ≥ 0.5) або не
     досягнутий;
   - точка руйнування катаракти ≤ точки руйнування гостроти;
   - час прогону ≤ 10 хв на звичайному ПК.
3. Звичайний режим працює як раніше (таблиця, `--max-ilr`, коди виходу)
   з новими пресетами.
4. README описує режим `--sweep`, геометрію перегляду і обмеження
   (оцінка «за одну фіксацію» для поля зору; наближена клінічна шкала
   метаморфопсії; OCR як модель читача).

## 12. Обмеження (для тексту роботи)

- Втрата поля зору оцінюється за одну фіксацію в центрі кожного екрана;
  реальний користувач рухає очима, тому ILR для скотоми й тунельного зору —
  оцінка зверху втрати за одну фіксацію, а не неможливість прочитати.
- Пороги CSF моделюють виявлення, а не розпізнавання літер; калібрувальний
  тест перевіряє узгодженість із гостротою, але не замінює дослідження з
  людьми.
- Зв'язок M-CHARTS → амплітуда синусоїди і коефіцієнти пожовтіння /
  засвітки катаракти — параметри моделі, а не клінічні вимірювання.
